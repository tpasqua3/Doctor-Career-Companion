MKOS LARGE SOURCE GOVERNANCE, CONFIDENCE SCORING, KNOWLEDGE OBJECT GENERATION, AND ONTOLOGY EXPANSION DIRECTIVE

Purpose

Large educational sources should never be skipped solely because of file size.

The objective is not to ingest entire textbooks as narrative content.

The objective is to transform educational resources into structured, retrievable, ontology-linked knowledge assets that participate in the knowledge graph, curriculum, assessment systems, educational functionality, confidence scoring systems, and retrieval engines.

Large files should be routed according to source category rather than rejected based on size.

==================================================
SOURCE ROUTING GOVERNANCE
==================================================

Every discovered source must be categorized before processing.

Source Categories:

1. Clinical Guidelines
2. Consensus Statements
3. Position Statements
4. Clinical Practice Recommendations
5. MKSAP
6. ACP Educational Assets
7. Textbooks
8. Board Review Resources
9. Blueprint Sources
10. Curriculum Sources
11. Educational Media
12. Other Registered Sources

File size alone must never determine whether a source is processed.

File size only determines processing method.

==================================================
GUIDELINE PROCESSING POLICY
==================================================

Guidelines remain primary clinical truth sources.

For guidelines:

Allow:

- full extraction
- recommendation extraction
- evidence extraction
- algorithm extraction
- threshold extraction
- risk stratification extraction
- decision pathway extraction
- knowledge object generation
- relationship generation

If large:

- chunk automatically
- process incrementally
- continue extraction

Do not skip guidelines because of size.

==================================================
MKSAP PROCESSING POLICY
==================================================

MKSAP serves as the primary educational interpretation layer.

For MKSAP:

Generate:

- source records
- chapter records
- section records
- topic records
- objective records
- concept records
- educational mappings
- blueprint mappings
- competency mappings
- curriculum mappings

Create knowledge objects around:

- diseases
- syndromes
- diagnoses
- treatments
- medications
- procedures
- pathophysiology
- epidemiology
- prevention
- prognosis
- clinical reasoning
- board-focused concepts
- educational objectives

Store structured concepts and mappings.

Do not depend on re-reading MKSAP to answer educational questions.

==================================================
TEXTBOOK PROCESSING POLICY
==================================================

Textbooks remain INDEX-FIRST.

Large textbooks must not be skipped.

Large textbooks must instead use index-first processing.

For every textbook:

Generate:

- source record
- textbook record
- edition record
- chapter records
- section records
- subsection records
- topic records
- concept records

Extract:

- table of contents
- chapter names
- section names
- topic names
- index entries
- glossary terms
- metadata

Create:

- ontology mappings
- blueprint mappings
- curriculum mappings
- specialty mappings
- competency mappings

Do not store textbook chapters as narrative content.

Do not reproduce textbook content.

Instead create structured educational representations.

==================================================
CONFIDENCE SCORING FRAMEWORK
==================================================

Every source, concept, relationship, knowledge object, learning objective, educational asset, recommendation, graph edge, and AI-generated artifact must carry a confidence score.

Confidence scores should not be generated solely by AI.

Confidence scores should be calculated deterministically whenever possible.

Confidence Score Components:

Source Confidence
Extraction Confidence
Mapping Confidence
Relationship Confidence
Educational Confidence
Retrieval Confidence
Consensus Confidence
Review Confidence

==================================================

==================================================
EXTRACTION CONFIDENCE
==================================================

Confidence should increase when:

- structured extraction succeeds
- multiple extraction passes agree
- source formatting is clear
- recommendation language is explicit

Confidence decreases when:

- extraction is ambiguous
- OCR quality is poor
- parsing failures occur
- conflicting results appear

==================================================
RETRIEVAL-FIRST REQUIREMENT
==================================================

When a learner requests:

- tutoring
- board review
- assessments
- explanations
- lessons
- concept reviews

System should first retrieve:

1. ontology entities
2. knowledge objects
3. graph relationships
4. educational assets
5. blueprint mappings
6. curriculum mappings
7. MKSAP mappings
8. textbook mappings

Rank retrieval results by:

- confidence score
- source quality
- relationship strength
- review status
- educational relevance

Only then invoke AI.

==================================================
AI CONFIDENCE GOVERNANCE
==================================================

AI-generated outputs should never automatically become trusted knowledge.

AI-generated content:

- starts with reduced confidence
- enters review queues
- receives source validation
- receives ontology validation
- receives graph validation

Confidence increases only after validation.

AI confidence must not exceed source confidence.

==================================================
TEXTBOOK SIZE GOVERNANCE
==================================================

Files above 25 MB must not be listed as failed solely because of size.

Instead:

1. Register source.
2. Record metadata.
3. Record file size.
4. Record source category.
5. Route to correct processing method.

Large textbooks:
→ Index-first workflow

Large MKSAP resources:
→ Educational extraction workflow

Large guidelines:
→ Chunked extraction workflow

Objective:

Never Skip
Always Register
Always Map
Always Index
Process According To Source Type
